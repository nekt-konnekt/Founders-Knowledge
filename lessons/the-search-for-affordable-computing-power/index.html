The search for affordable computing power.

Three hosting approaches, six concurrent AI agents, and a $10–$20 monthly budget. How do we buy enough capacity without paying for a number that tells us very little?

We want to run Hermes Agent and Claude Code in a client-facing service, with six agents able to work at the same time. Our current computer is not a comfortable home for that workload, and our infrastructure budget is $10–$20 a month. It is tempting to compare hosting plans by the number of vCPUs they advertise. That shortcut can send us towards the wrong server.

01 — DEFINE THE JOB BEFORE THE SERVER

Six agents running is not the same as six agents working hard.

Before comparing providers, we need to be precise about what the machine will do. If our agents call hosted AI models, the VPS usually runs the agent processes, tools, integrations, files and background jobs. The model inference itself happens with the external model provider. That is different from trying to load and run a large model locally, which may require substantially more memory and possibly a GPU.

Concurrency matters, but it does not tell the whole story. Six agents waiting for API responses may use modest CPU. Six agents parsing large files, running browser sessions, executing code or processing many jobs at once can place very different demands on CPU, RAM, disk and network.

For a client-facing service, raw capacity is only part of the job. We also need dependable uptime, secure storage of credentials, separation between clients, logs, backups and a recovery path when a process fails. Those requirements should be part of the comparison, not a footnote after we choose the cheapest plan.

02 — SEPARATE THE TERMS

A VPS is the environment. A vCPU is one resource inside it.

A virtual private server (VPS) is a virtual machine rented from a hosting provider. It gives us an operating environment with a package of resources and features: virtual CPU capacity, memory, storage, network access and some level of isolation. The package, management tools, backup options and terms vary by provider.

A virtual CPU (vCPU) is a unit of CPU capacity allocated to that virtual machine. It is not a standardised measure of real-world speed across every provider. The underlying processor, whether CPU resources are shared or dedicated, scheduling policies and the workload itself all affect the work a vCPU can complete.

So “four vCPUs” does not automatically mean a server is twice as fast as a two-vCPU server. Nor does “eight gigabytes of RAM” tell us whether a particular workload will be responsive. Specifications describe the offer; a representative test tells us how well that offer fits our job.

!
Do not confuse hosting with model capacity

A larger VPS does not automatically give an agent a better AI model, more model context, higher API limits or cheaper tokens. Those are usually controlled by the model provider and our application design.

03 — THREE APPROACHES, NOT THREE IDENTICAL PLANS

What are we really buying?

Hetzner and Contabo sell general-purpose virtual servers. Agent37 offers managed agent hosting and a metered cloud API for persistent agent instances. These are different operating models, so a fair comparison must include the work we have to do ourselves—not just the advertised CPU and RAM.

Hetzner: control and a conventional cloud server

Hetzner’s cost-optimised cloud range is positioned for development, testing and lighter workloads, with shared CPU resources and a choice of server sizes. The provider says these plans are intended for low-to-medium CPU usage; availability can vary, and its published prices and plan availability have changed. Check the current region, plan and checkout total rather than relying on an old comparison.

The benefit is control: we can install the software and supporting services we need and shape the environment around our workflow. The cost is operational responsibility. We must secure the machine, apply updates, monitor resources, configure backups, manage secrets and troubleshoot failures. That work is real even when the server bill is low.

Contabo: more advertised resources for a low fixed price

Contabo’s US pricing page lists Core VPS options such as Cloud VPS 4 with 4 vCPU cores, 8 GB RAM and 100 GB SSD, and Cloud VPS 6 with 6 vCPU cores, 12 GB RAM and 200 GB SSD. At the time of research, the page displayed introductory prices of $4.40 and $6.00 per month for those plans under a 24-month term. Pricing can differ by storefront, currency, location, taxes and commitment; treat these as a dated indication, not a guaranteed checkout quote.

Those resource bundles make Contabo worth testing against our workload. But a higher advertised vCPU count is not proof of higher throughput, and a long billing commitment is a risk if the machine fails our test. Before paying, verify the renewal price, billing term, server location, backup options, network limits and cancellation conditions. As with any self-managed VPS, we remain responsible for the software and its security.

Agent37: pay for an agent environment, or for a metered sandbox

Agent37’s managed Hermes hosting lists a Basic plan at $3.99 per month with 1 vCPU, 4 GB RAM and 8 GB disk. It is designed to make a Hermes instance easier to launch and maintain. That is not the same thing as a general-purpose server sized for six independent agents or an arbitrary Claude Code workflow. We must confirm the supported software, concurrency and resource limits before treating it as a fit.

Agent37 Cloud API uses metered compute and disk billing. Its pricing page currently shows a 2-vCPU, 4-GB instance at about $4.76 per month if it runs continuously, plus approximately $0.36 per month for 4 GB of disk. The total is therefore about $5.12 for that example, before model usage or other services. Compute charges stop while a sandbox is asleep, while disk charges continue until the instance is deleted. The actual bill depends on size and running time.

The appeal is that a purpose-built environment can reduce server administration and may make per-customer agent instances easier to provision. The trade-off is that metered usage, supported workflows and the provider’s platform model need to match our service. A low example price does not prove that six agents can run concurrently within budget.

!
Price is not a like-for-like benchmark

These examples differ in resource size, management, billing model and contract term. Provider prices were checked on 18 October 2026 and can change. Recheck the official pages and final checkout price before committing.

04 — CHOOSE WITH EVIDENCE

Use the table to shortlist. Use a test to decide.

The meaningful comparison is not “which provider has the most vCPUs per dollar?” It is “which option can run our actual service reliably, with acceptable operational effort and a total cost we can sustain?”

THE TRADE-OFF AT A GLANCE

  • Self-managed VPS: most control over the environment; we carry setup, security, monitoring and recovery work.
  • Managed agent hosting: less routine server administration; we must confirm product fit, concurrency and platform limits.
  • Metered agent sandbox: costs can follow actual runtime; always-on workloads and persistent disk still have a cost, and usage must be estimated carefully.

With a $10–$20 monthly infrastructure budget, a self-managed VPS with enough memory is a sensible candidate for a controlled trial. Contabo’s advertised resource bundles make it one candidate; Hetzner is another if a suitable plan is available at the right price. Agent37 may be attractive if the managed or metered model supports our exact workflow. None is a proven winner until we run the same workload on it.

Run a test that could change the decision

Use a small test plan before moving client work to the server:

  • Deploy the real stack. Use the same agent software, integrations, tools and model APIs we intend to use in production.
  • Run six agents concurrently. Include realistic browser, file, API and background jobs—not six idle processes.
  • Measure the bottlenecks. Record peak and sustained RAM, CPU use, disk pressure, response latency, failed jobs and restarts over a representative period.
  • Test failure and recovery. Restart a process, simulate a temporary API failure, check logs, restore a backup and verify that one client cannot access another client’s data.
  • Calculate the full monthly cost. Include the server or sandbox, storage, backups, model tokens, search or integration fees, taxes and any required monitoring.

Decide the pass conditions before running the test. For example: all six agents finish the defined workload without out-of-memory kills; jobs recover after a process restart; credentials and client data remain separated; and the projected monthly bill stays inside the agreed ceiling. Set an acceptable response time based on the service you promise clients, not an arbitrary benchmark.

If the test fails, do not automatically buy a larger server. First identify the bottleneck. It may be RAM, CPU, a single-threaded process, API rate limits, disk performance, a browser workload or application architecture. Paying for more vCPUs will not fix every one of those problems.

05 — THE BIGGER LESSON

Buy the capacity your service needs—not the biggest number on a plan.

Infrastructure is part of the business model. A cheap server that repeatedly interrupts client work is not cheap in practice. A larger plan that sits idle may be wasteful. And a managed service that saves hours of maintenance can be worth more than raw compute savings—if it supports the workflow we actually need.

Our next move is not to declare a provider the winner from its marketing page. It is to shortlist a self-managed VPS and, if the workflow fits, a managed or metered agent option; run the same six-agent workload; then compare reliability, operational effort and full cost. The evidence from that test should decide where we deploy.

THE TAKEAWAY

A vCPU count tells you part of what you are buying. The right hosting choice is the one that passes your real workload and recovery tests at a total cost your business can sustain.
